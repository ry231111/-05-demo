# 訪談 → 設計對照

來源：好事大平台訪談文件（問題搜集＋10/31 逐字稿轉會議紀錄）。規則細節見 `rules/rules.json`（每條的 `origin` 欄位）。

## 一、主辦方怎麼看（決定我們的重點）
- 評審**不看名單準確率**，看「解決誰的痛點、在什麼時刻」，越聚焦越好（說明會一）。
- 成功標準：同仁看了覺得「明天就想用」；AI 六、七成吻合就夠（說明會一、Q8）。
- 期待：「讓旅程資料自動拼出畫像，顧問只補腦中那一版」（說明會一、三）。
→ 我們的定位：**PM 接到一句話需求的那一刻**，幾分鐘拿到附依據的第一波名單；資深顧問只要勾選、補一句話。

## 二、八個痛點 → 我們的對應
| 痛點 | 我們怎麼做 |
|---|---|
| 1 資料跟著 PM 不跟著組織 | 每家組織一份 MD（`output/orgs/`），所有接觸紀錄、筆記、PM 回饋都寫進同一份 |
| 2 最有價值的判斷只在腦中 | 把顧問的「訊號→解讀→行動」寫成 18 條規則，解讀寫在畫面上，不只給分數 |
| 3 沒有例行收集機制，最有效的記錄在雙週全會 | 第二輪回饋只要「勾選＋選原因＋一句話」，適合在雙週全會當場填；回饋自動寫回組織檔 |
| 4 師徒制，能力無法複製 | 新 PM 也能看到每條推薦背後的規則和出處 |
| 5 同樣數據相反狀況（情境 A／B） | R04、R05：上課次數一樣，用走訪／後追的文字區分 |
| 6 要判斷半年後還在不在 | R06 主管換人、R07 計畫太多、R16 久未接觸；新資料優先的時間加權 |
| 7 組織池小，名單要年年不同 | R09 近期合作過降分；條件不夠時自動放寬並顯示放寬了什麼 |
| 8 不同情境名單邏輯不同 | 四種情境（實驗課／例行課／企業陪跑／年度走訪）各有一組權重 |

## 三、流程對應（Q5、Q6）
訪談裡的實際流程：結構化資料＋同事直覺 → 第一波名單 → 重點電訪（先「關心」不直接邀請）→ 電訪結果回饋給同事 → 同事決定 → 一排名字＋現況觀察 → 企業決定。

| 實際流程 | 系統節點 |
|---|---|
| 一句話需求 → 釐清動機 → 推導條件（Q2） | 節點 3：一句話需求 → 條件（表單或 AI 轉換，PM 確認） |
| 結構化資料＋直覺 → 第一波名單 | 節點 3：規則算分＋AI 從自由文字抽取的訊號 |
| 重點電訪，先關心 | 每家附「電訪問題」，用關心的口吻（Q6） |
| 電訪結果回饋給同事、同事決定 | 節點 4：勾選符合／不符合＋原因 → 重排，寫回組織檔 |
| 一排名字＋現況觀察；理由在前面就決定 | 產生 Claude 提示詞寫理由，每點附紀錄編號，貼回自動驗證 |
| 企業選 10 家，給約 50 家評估名單 | 企業陪跑情境預設 5 倍名單 |

## 四、AI 怎麼用、怎麼確認是對的（對應評分 30%）
- 參考他們自己做過的實驗（Q8）：會議紀錄 → AI 產標籤 → 問資深顧問認不認同 → 看新同事用標籤篩出的名單符不符合顧問的想像，約 70% 吻合。
- 我們做的：AI 抽取標籤時**必須附原文**，程式檢查原文是否真的存在，對不上就丟掉；推薦理由要附紀錄編號，貼回後自動檢查。
- 可以加的功能：組織速覽頁的每個 AI 標籤旁加「認同／不認同」，顧問一鍵校正（就是 Q8 的流程，變成日常操作）。

## 五、還沒問清楚 → 無敵星星候選
1. **哪種錯誤最不能接受：漏掉適合的組織，還是推薦了接不住的組織？**（題綱有，訪談沒回答；決定負面訊號要扣多重）
2. 「這份名單你們會直接用嗎？還缺什麼才敢用？」（對應 40% 評分）
3. 陪跑分級 A/B/C 的意思？（只有 11 家有分級，且沒有理由，痛點2）
4. 財報晚交、主管換人這類組織，實際上會降低優先，還是照樣邀請？

## 六、資料面提醒
- 主鍵：手冊寫「組織編號」，說明會寫「統編」；`config/columns.json` 兩個都認。
- 入會必收「成立年數」，但手冊的 schema 沒有這個欄位。如果官方資料有這欄，再加進對照表。
- 「服務對象」在他們的真實系統裡沒有欄位（痛點2），官方假資料裡可能也會缺。
